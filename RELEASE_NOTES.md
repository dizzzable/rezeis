# Rezeis Admin v0.9.7.20

Два исправления по сообщениям из боя. Оба про то, что оператор видит на экране: одно портило данные при каждой синхронизации, второе оставляло тревогу без выхода. Парная версия кабинета не менялась — **[Reiwa v0.9.7.14](https://github.com/dizzzable/reiwa/releases/tag/v0.9.7.14)**, обновлять его не нужно.

## 👤 Имя профиля Remnawave больше не становится публичным username

Подписчик, зарегистрировавшийся в вебе с логином `Lant35`, показывался оператору с публичным username `@2GET_Lant35_sub`. Эту строку никто не вводил: это `{prefix}_{identity}_{suffix}` — имя, которое **наш же** сервис именования выдал профилю в Remnawave.

Импортёр писал его обратно в учётку безусловно, **на каждом проходе синхронизации**. Поэтому исправление руками не держалось: следующий проход возвращал имя профиля.

Признак принадлежности уже был и однозначен: в описание каждого созданного нами профиля кладётся `reiwa_id`. Профиль, который его называет, — наш, и его username ничего не сообщает о человеке. Профиль без него — чужой, импортированный из другой панели, и там username может быть единственным существующим именем; ради этого случая поле и заполняется вообще.

Правило теперь такое: **своё имя не переносим никогда; чужое — только в пустое поле и никогда поверх существующего.** Второе не менее важно первого: этот код выполняется при каждой синхронизации, и без него ни оператор не удержит поправку, ни подписчик — выбранное имя.

Уже испорченные значения выпуск не чинит: он останавливает порчу. Поправленное вручную теперь остаётся поправленным.

## 🧭 Тревога о дубле профиля называет средство

Оператор получал сообщение «две живые подписки на одном профиле Remnawave, удаление любой отклонено — распутайте их» и больше ничего. Средство, которое распутывает ровно эту пару, существует, но живёт на странице **«Подписки»**, а тревога приходит из карточки пользователя.

Теперь сообщение называет инструмент, где он находится, и что он по умолчанию только показывает, ничего не меняя.

**Как убрать дубли, оставшиеся после перехода панели с 2.x на 3.x:** страница «Подписки» → «Сведение дублей». Она сама прогоняет сверку связей вхолостую, сама находит пары по всему дереву и обходит их страницами — указывать пары руками не нужно. Сухой прогон показывает, сколько пар свело бы; настоящий сводит. Выживает **старшая** строка — та, на которой история и платежи.

Синхронизация из «Импорта пользователей» этого не делает и делать не будет: у импортёра нет пути снятия строки, он умеет только создавать и обновлять. Автоматическое удаление здесь было бы опасно — строка эпохи 2.x хранит uuid, адресация по нему откатывается на короткий идентификатор из сохранённого `config_url` и находит **живой** профиль.

**Мутацией: 2 из 2.** Снять проверку `reiwa_id` — падает тест «не кладёт наше сгенерированное имя в публичный username». Убрать условие «только в пустое поле» — падает тест «не перезаписывает существующее имя». Число собранных тестов в обоих прогонах держалось на 16; прогон, в котором оно **падает**, недействителен — это признак того, что набор не собрался, а не что мутация поймана.

Заглушку пользователя в наборе пришлось переписать: она ничего не записывала и умела только соглашаться. Сквозная заглушка сделала бы тест «не перезаписывает существующее имя» зелёным и против сервиса вообще без проверки.
