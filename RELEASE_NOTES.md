# Rezeis Admin v0.9.7.81

Выпуск про Platega: оплаченный платёж больше не теряется без колбэка, каждый платёж передаёт Platega покупателя, а вернуть деньги можно прямо из панели — целиком или частично, и покупка при этом отменяется.

- **Колбэк Platega не дошёл — платёж всё равно засчитан.** Панель сама спрашивает Platega о разовых платежах и не отменяет оплаченный по таймауту.
- **`metadata` в каждом платеже Platega.** Platega сделала поле обязательным: панель передаёт постоянный идентификатор покупателя и его ID.
- **Кнопка «Вернуть» для Platega** — как у ЮKassa: полностью или частично, с проверкой баланса и комиссии у Platega.
- **Возврат отменяет покупку.** Продление теперь снимает купленные дни, а не уходит на ручной разбор. При частичном возврате — галочка «Отменить покупку».
- **Platega отклонила возврат** — новая карточка «⛔ Провайдер отклонил возврат».

⚠️ **Выпускается одна панель, кабинет обновлять не нужно.** API между панелью и кабинетом не менялся: эта панель работает с кабинетом 0.9.7.63 и предыдущими, с которыми работала 0.9.7.80. Подробности — раздел «🤝».

✅ **Миграций, новых переменных окружения и изменений в `docker-compose.yml` и `.env.example` нет.** Обновление: `docker compose pull && docker compose up -d`.

## 📌 Коротко

- **Разовые платежи Platega:** каждые 5 минут панель спрашивает Platega о неоплаченных платежах старше 3 минут. Перед отменой по таймауту — ещё раз. Раз в час — об отменённых за последние 7 дней. Подтверждённый у Platega платёж выдаётся покупателю, даже если колбэк так и не пришёл.
- **Платежи от 05.11 с «Callback неуспешен»:** после обновления панель найдёт их сама в течение часа, если Platega подтверждает оплату, и выдаст покупку. Это работает, пока платежам меньше 7 дней, — то есть при обновлении до 12.11.
- **`metadata.user_email`:** Telegram ID покупателя в виде `{id}@telegram.org`, иначе его почта, иначе `{ID в панели}@mail.ru`. Плюс `metadata.userId`.
- **«Вернуть» для Platega:** карточка пользователя → вкладка «Операции» → у платежа кнопка «Вернуть».
- **После возврата:**
  - новая подписка отключается;
  - продление снимает купленные дни;
  - докупка заканчивается.

  Работает для всех дверей возврата: «Вернуть», «Отметить возврат», уведомление провайдера о возврате и чарджбэк. Любой возврат, как и раньше, выключает автосписание клиента.

Перепроверка из этого выпуска страхует, но не заменяет колбэки: без них панель узнаёт об оплате с задержкой до 8 минут, а об итоге возврата — только по колбэку. Что проверить — раздел «🔌».

Панель перепроверяет только платежи моложе 7 дней: если обновляетесь после 12.11, отправьте эти колбэки повторно из личного кабинета Platega, когда почините HTTPS.

## 🔌 «Callback неуспешен» — оплаченные платежи без колбэка

**Как было.** О разовом платеже Platega панель узнавала только из колбэка. Platega пробует доставить его три раза, а потом сама больше не шлёт. Если колбэк не дошёл, платёж висел «в ожидании», а через 30 минут панель отменяла его как брошенный счёт. Деньги у вас, а покупатель ничего не получил, и карточки оператору не было. Так случилось 05.11 с двумя платежами: сервер Platega не смог установить HTTPS-соединение с панелью.

**Как стало.** Панель спрашивает Platega сама — запросом `GET /transaction/{id}`, который Platega для этого и рекомендует:
- **каждые 5 минут** — о каждом неоплаченном разовом платеже старше 3 минут: первый раз — через 3–8 минут после создания счёта;
- **перед отменой по таймауту.** Если Platega подтверждает оплату — платёж засчитывается и выдаётся. Если отменён у Platega — отменяется по её слову. Если Platega ещё считает его открытым или не отвечает — панель ждёт до часа с момента создания, потом отменяет по своему таймауту, как раньше. Если Platega такого платежа не знает — отмена через 30 минут, как раньше;
- **раз в час** — о платежах за последние 7 дней, которые панель отменила сама и ни разу не выдала. Пока Platega не назовёт итог: если подтверждает оплату — платёж оживает и выдаётся, как при опоздавшем колбэке.

Ответ Platega проходит тот же путь, что колбэк: сверка суммы, выдача покупки, кэшбэк, партнёрская комиссия, карточки. Колбэк, пришедший после, ничего не повторит.

**Подписки Platega** (автосписание) панель и раньше сама проверяла у Platega каждые 10 минут, так что их списания не терялись.

**Что проверить на сервере.** Platega принимает колбэк только по HTTPS, с сертификатом доверенного центра. Шаблоны прокси из репозитория для этого подходят. Частые причины:
- неполная цепочка сертификата: в nginx или angie `ssl_certificate` должен указывать на `fullchain.pem`;
- домен панели недоступен из российских сетей;
- перед 443-м портом стоит что-то, что рвёт незнакомых клиентов.

Проверка цепочки — должно быть `Verify return code: 0 (ok)` и строки `0 s:` и `1 s:`:

```bash
openssl s_client -connect ДОМЕН:443 -servername ДОМЕН </dev/null 2>/dev/null | grep -E "Verify return code|^ *[0-9] s:"
```

Точную причину называет «inner exception» в логе Platega — его можно запросить у их поддержки. После починки колбэки можно отправить повторно из личного кабинета Platega.

## 📧 «Нужна вот такая доработка» — покупатель в каждом платеже Platega

**Как было.** Панель не передавала Platega `metadata`. Platega знала только сумму, и каждый платёж одного покупателя выглядел как платёж нового. По документации от 30.10 (подписки) и 04.11 (разовые платежи) это поле обязательно.

**Как стало.** Каждый запрос создания платежа Platega — разовый с выбранным способом оплаты, разовый с выбором способа на странице Platega и оформление подписки — несёт `metadata`:
- `user_email` — постоянный адрес покупателя, одинаковый во всех его платежах, по правилам из памятки Platega:
  1. есть Telegram — `5512345678@telegram.org` (числовой ID, он не меняется);
  2. нет Telegram, есть почта — почта покупателя как есть: сначала из карточки, затем из веб-аккаунта (та же, куда панель шлёт письма);
  3. нет ни того ни другого — ID покупателя в панели `@mail.ru`;
- `userId` — ID покупателя в панели. По документации Platega для некоторых категорий магазинов без него отключается антифрод.

Покупатель, который позже привяжет Telegram, сменит адрес один раз: с почты на `@telegram.org`.

## ↩️ «Кнопки, чтобы вернуть в ручном режиме» — возврат Platega из панели

**Как было.** Кнопка «Вернуть» работала только для ЮKassa. Платёж Platega можно было вернуть только в кабинете Platega, а потом нажать «Отметить возврат».

**Как стало.** Карточка пользователя → вкладка «Операции» → у платежа Platega кнопка **«Вернуть»**:
- в окне панель сразу спрашивает Platega, можно ли вернуть платёж. Если на балансе у Platega не хватает денег на возврат, окно так и скажет. Если Platega берёт комиссию за возврат — строка «Комиссия провайдера за возврат: … RUB»;
- **поле «Сумма возврата» пустое — вернётся вся сумма.** Меньшая сумма — частичный возврат. Если Platega возвращает этот платёж только целиком, поле закрыто;
- повторное нажатие не создаст второй возврат: Platega узнаёт ту же операцию;
- если Platega возьмёт возврат на ручную проверку, панель скажет: «Провайдер взял возврат на ручную проверку: деньги уйдут после его решения». Покупка тогда тоже отменится только после решения Platega.

Кнопкой не возвращаются **оформление автосписания Platega и его списания**: у них в панели нет номера платежа Platega. Окно «Вернуть» так и скажет: верните в кабинете Platega и нажмите «Отметить возврат».

Возвраты ЮKassa работают как раньше, плюс новая галочка из следующего раздела.

## ✂️ Что отменяется после возврата

**Как было.** Полный возврат отключал подписку, только если это первая покупка и других оплат по подписке не было. Возврат за **продление** ничего не менял в подписке — «поправьте вручную». Частичный возврат не отменял ничего.

**Как стало — полный возврат** (любая дверь: «Вернуть», «Отметить возврат», уведомление провайдера о возврате, чарджбэк):
- **новая покупка** — подписка отключается сейчас;
- **продление** — с подписки снимаются дни, купленные этим платежом. Продлили на 30 дней — срок сдвигается на 30 дней назад. Если осталось меньше, подписка заканчивается сейчас. Дни, оплаченные раньше, остаются. Если продление ещё не началось (было оплачено заранее), его будущий период отменяется. Новый срок уходит в Remnawave;
- **новая покупка, которую потом продлевали** — снимаются только её дни, продления остаются (раньше — на ручной разбор);
- **продление сразу нескольких подписок** одним платежом — с каждой снимаются её дни;
- **докупка** — заканчивается сразу, как и раньше;
- партнёрская комиссия, реферальная награда, кэшбэк и чек «Мой налог» отменяются, как и раньше.

**Частичный возврат** — в окне «Вернуть» под суммой галочка **«Отменить покупку»**, по умолчанию включена:
- **с галочкой** — покупка отменяется так же, как при полном возврате. Если провайдер ещё не провёл возврат (у ЮKassa он «в обработке», у Platega — на ручной проверке), покупка отменится, когда он подтвердит возврат;
- **без галочки** — клиент сохраняет всё купленное: например, если это компенсация за простой.

При частичном возврате, с галочкой или без, партнёрская комиссия, реферальная награда, кэшбэк и налоговый доход не откатываются — даже за возвращённую часть, — и платёж остаётся оплаченным. Если потом вернуть и остаток, деньги откатятся полностью, а дни второй раз сниматься не будут.

**Подписку панель не трогает — поправьте вручную, если нужно**, в этих случаях (отдельной пометки в карточке нет):
- смена тарифа;
- покупка дополнительной подписки;
- бессрочная подписка;
- подписка, заблокированная оператором;
- продление, оплаченное до смены тарифа;
- будущий период продления, к которому уже привязана докупка;
- платёж, по которому панель не знает, сколько дней он купил.

Клиенту никакой кнопки «запросить возврат» не появилось: возврат — только решение оператора в панели.

## ⛔ Platega отклонила возврат

Возврат Platega проходит не мгновенно: Platega берёт его в работу, а итог присылает колбэком. Панель учитывает возврат сразу, как только Platega взяла его в работу, — кроме ручной проверки: тогда только после решения Platega. Если Platega потом отклонит частичный возврат — колбэк `PARTIALLY_REFUNDED` с отказом — панель:
- убирает этот возврат из учёта. Сумма возвращённого становится той, что называет Platega;
- присылает карточку **«⛔ Провайдер отклонил возврат»** со строкой «Возвращено всего». Если покупка уже была отменена с этим возвратом, карточка так и пишет: восстановите её вручную или повторите возврат. Если этим возвратом сумма дошла до полной и панель уже провела платёж как возвращённый целиком, карточка говорит и это: вернуть платёж обратно в оплаченные панель сама не может, верните остаток в кабинете Platega или восстановите покупку вручную.

Успешный частичный возврат из колбэка `PARTIALLY_REFUNDED` учитывается один раз, даже если о нём сообщили и панель, и Platega.

## ↩️ Откат

На 0.9.7.80 — без миграций и без потери данных. Пометки, которые эта версия пишет в платежи («проверено у Platega», «покупка отменена с возвратом», учёт возвратов Platega), старая версия просто не читает. Вернётся старое поведение:
- платежи без колбэка снова отменяются через 30 минут;
- `metadata` не передаётся;
- «Вернуть» — только ЮKassa;
- продление при возврате не откатывается.

## 🔍 Что не проверено

- **Живые возвраты через Platega.** Запросы `cancel-supported`, `cancel` и `cancel-partial` сделаны по документации Platega и проверены автотестами, а не на настоящем платеже. Первый возврат стоит сделать на небольшой сумме и сверить с кабинетом Platega.
- **Колбэк `PARTIALLY_REFUNDED`** — по образцу из документации Platega, живой не приходил.
- **Перепроверка платежей** — по документации `GET /transaction/{id}`. Ответ живого сервера Platega не сверялся.
- **Снятие дней** проверено на PostgreSQL с настоящей цепочкой сроков, но не на живой Remnawave: новый срок уходит туда обычной синхронизацией.
- **Причина ошибки TLS на вашем сервере** не найдена — домен панели нам неизвестен.

## 🚫 Чего этот выпуск НЕ делает

- **Не чинит HTTPS на вашем сервере** — колбэки Platega по-прежнему не дойдут, пока его не поправить.
- **Не добавляет кнопку «Вернуть» другим шлюзам** — только ЮKassa и Platega. Остальные — «Отметить возврат».
- **Не возвращает кнопкой оформление автосписания Platega и его списания** — через кабинет Platega и «Отметить возврат».
- **Не узнаёт об отказе Platega в полном возврате:** по документации Platega такой отказ колбэком не сопровождается. Сверяйте полные возвраты с кабинетом Platega.
- **Не откатывает смену тарифа** — она остаётся на ручной разбор.
- **Не даёт клиенту запросить возврат** — только оператор в панели.
