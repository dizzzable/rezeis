# Rezeis Admin v0.9.7.80

Выпуск безопасности: в образе панели обновлены библиотеки, на которые GitHub (сканер Trivy) открыл 12 предупреждений, и сверх них — zod. Новых функций и изменений в поведении нет.

- **Сканер «Code scanning»:** все 12 открытых предупреждений по образу панели закрыты обновлением — body-parser, multer, follow-redirects, qs, nodemailer, fast-uri.
- **Сверх сканера:** zod 4.5.4 → 4.6.7 — `npm audit` отмечает у старой версии уязвимость уровня high, Trivy её пока не показывает.

⚠️ **Выпускается вместе с Reiwa 0.9.7.62, но порядок обновления не важен.** API между панелью и кабинетом не менялся: эта панель работает с кабинетом 0.9.7.61, а кабинет 0.9.7.62 — с панелью 0.9.7.79. Подробности — раздел «🤝».

✅ **Миграций, новых переменных окружения и изменений в `docker-compose.yml` и `.env.example` нет.** Обновление: `docker compose pull && docker compose up -d`.

## 📌 Коротко

- **body-parser 2.3.0 → 2.4.0** — сжатое тело запроса больше не может уронить процесс (high). Касалось панели напрямую: она разбирает тело каждого JSON- и form-запроса, в том числе без входа.
- **multer 2.4.0 → 2.5.0** — оборванная загрузка файла (high). Только загрузки в админке.
- **follow-redirects 1.16.0 → 1.16.2** — утечка заголовков при переадресации на другой домен (high ×2). Все исходящие запросы панели через axios: Remnawave, платёжные шлюзы, вход через сторонние сервисы и другие.
- **nodemailer 10.1.1 → 10.2.1** — разбор адресов в письмах (medium ×3).
- **qs 6.16.0 → 6.17.1** и **fast-uri 3.1.8 → 3.1.9** — уязвимый код в панели не вызывается, обновлены, чтобы закрыть предупреждения.
- **zod 4.5.4 → 4.6.7** — проверка слишком больших списков могла съесть память (high по `npm audit`).

## ✅ Что сделать после обновления

Ничего, кроме самого обновления. Предупреждения во вкладке **Security and quality → Code scanning** репозитория закрываются сами: Trivy проверяет образ при каждой сборке `main` и тега и помечает исчезнувшие уязвимости как исправленные. Если предупреждение не закрылось после сборки — значит, сканер нашёл версию, которой в этих заметках нет; это стоит прислать.

## 🛡️ «Опа, пора исправить» — 12 предупреждений сканера

**Как было.** Во вкладке **Code scanning** репозитория `rezeis` висело 12 открытых предупреждений по образу панели, из них 4 уровня high. Все — в сторонних библиотеках внутри `node_modules` образа, ни одно — в коде панели.

**Как стало.** Каждая библиотека поднята до версии, где уязвимость исправлена. В блокировке зависимостей сменились только эти пакеты и два, которые body-parser тянет за собой (`content-type` 2.1.0, `iconv-lite` 0.7.3).

| Пакет | Было → стало | Что исправлено | Касалось ли панели |
|---|---|---|---|
| body-parser | 2.3.0 → 2.4.0 | High: ошибка потока распаковки сжатого тела не перехватывалась — процесс мог упасть | **Да.** Панель разбирает тело каждого JSON- и form-запроса, сжатое тоже, — в том числе на маршрутах без входа, например в вебхуках оплат |
| multer | 2.4.0 → 2.5.0 | High: отказ в обслуживании при обрыве запроса во время проверки файла | Только загрузки в админке — бэкап, бот, рассылки, FAQ, импорт, задания, настройки (иконки, логотип бренда, логотип QR). Нужен вход администратора |
| follow-redirects | 1.16.0 → 1.16.2 | High ×2: заголовки, которые положено убирать при переадресации на другой домен, в некоторых записях проходили фильтр | Через axios — все исходящие запросы панели: Remnawave, «Мой налог», платёжные шлюзы, вход через Google, Яндекс, Mail.ru, GitHub и Telegram, курсы валют, проверка обновлений, ИИ, оповещения. axios по умолчанию проходит до 5 переадресаций. Утечка возможна, только если один из этих серверов сам переадресует на чужой домен |
| nodemailer | 10.1.1 → 10.2.1 | Medium ×3: разбор адреса мог превратить часть текста в лишнего получателя | Письма панели: коды, уведомления, рассылки по почте, тестовое письмо из настроек. Получатель — в том числе адрес, который клиент сам ввёл при привязке почты: код уходит на него до подтверждения, а проверяется только формат (`@IsEmail`). Прошёл бы проверку формата адрес из описания уязвимости — не проверялось |
| qs | 6.16.0 → 6.17.1 | Medium: исключение при сборке строки запроса из массива | Нет: панель строки запроса только разбирает, сборку (`qs.stringify`) не вызывает |
| fast-uri | 3.1.8 → 3.1.9 | Medium ×2, Low ×2: разбор и нормализация адресов | По разбору 07.08.2026 — нет: библиотека лежит в образе через prisma, но подгружается только командой `prisma init`, которую контейнер не выполняет. Путь с тех пор сменился (через `@prisma/streams-local`) и заново не перепроверялся |

**Почему nodemailer 10.2.1, а не самый свежий 10.3.1.** Исправление вышло в 10.1.4, а 10.3.1 был опубликован за два дня до этого выпуска. Свежая публикация — самый частый момент подмены пакета, поэтому взята 10.2.1: в ней исправление есть, и ей больше недели. qs 6.17.1 тоже свежий; его изменения прочитаны в опубликованном архиве — исправления разбора и сборки строки запроса, защита от ключа `__proto__` и новый формат `WHATWG` для сборки. Ни сети, ни скриптов установки.

## 🧩 Сверх списка сканера: zod

**Как было.** zod 4.5.4. `npm audit` отмечает у всех версий ниже 4.6.6 уязвимость уровня high ([GHSA-mrhx-c7xc-m3w5](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5)): проверка слишком большого списка, множества или словаря с ограничением размера сначала перебирала все элементы и только потом сверяла размер — память могла кончиться. Trivy её пока не показывает.

**Как стало.** zod 4.6.7 — размер проверяется до перебора. Версия закреплена точно, как и раньше. У 4.6.7 есть подпись npm и SLSA-провенанс. В репозитории zod в сентябре был эпизод с вредоносными коммитами; по заметке авторов к 4.6.6, они откачены в тот же день и в npm не публиковались.

Заодно 4.6 исправляет удержание памяти в рекурсивных схемах — регрессию, появившуюся в 4.5.

## 🔍 Что не проверено

- **Сами уязвимости не воспроизводились.** Оценка «касалось ли панели» — по коду: кто вызывает библиотеку и на каких маршрутах. Сжатый «битый» запрос на живую панель не отправлялся.
- **Почта через настоящий SMTP** на nodemailer 10.2.1 не отправлялась — проверено тестами.
- **Загрузка файлов в админке** на multer 2.5.0 и **исходящие запросы** (Remnawave, шлюзы, вход через сторонние сервисы) на follow-redirects 1.16.2 проверены только тестами.
- Закроет ли Trivy все 12 предупреждений, станет видно после сборки `main` на GitHub.

## 🚫 Чего этот выпуск НЕ делает

- **Не меняет поведение панели.** Только версии библиотек и номер выпуска.
- **Не обновляет зависимости веб-интерфейса панели** (`rezeis-admin/web`). Их нет в образе, и Trivy их не сканирует. `npm audit` находит там follow-redirects и zod: follow-redirects — серверная часть axios и в сборку для браузера не попадает, а zod в браузере может повредить только вкладке самого администратора.
- **Не включает Dependabot.** Единственный сканер по-прежнему Trivy по опубликованному образу.
