# Объединённые тарифы (связки) — описание, настройка, инструкция по кнопкам

Документ описывает функцию «Объединённые тарифы»: что она делает, как ей пользоваться в
панели, что видит клиент в кабинете и боте, что настраивается на сервере и что делать, если
ссылка не выдаётся. Актуален для сборок **Rezeis Admin 0.9.7.81** и **Reiwa 0.9.7.63**
(ветки с этой функцией — `main` форков `Asteliat/rezeis` и `Asteliat/reiwa`).

---

## 1. Что это такое

Связка — это **ровно два тарифа**, которые продаются и выдаются как **одна подписка**:

- у клиента **одна ссылка** на ноды обоих тарифов (её отдаёт отдельный сервис склейки);
- у клиента **один лимит устройств** на эту подписку;
- в VPN-приложении видно **один тариф** (его название, трафик и срок);
- в кабинете и боте это **одна карточка** и **одно приветствие**, а не две подписки.

Связка живёт в каталоге как **свой тариф**: имя связки становится именем тарифа, и он
выдаётся из карточки клиента. **Через кассу он не продаётся** — его выдаёт оператор.

Технически:

```
клиент → https://<домен>/merge/<токен> → сервис remnawave-subscription-merge
                                              │  GET /api/internal/merge-links/<токен>/sources
                                              ▼
                                        панель Rezeis (профили в Remnawave)
                                              │
                                              ▼
                                    две подписки Remnawave → одна клиентская
```

Если `MERGE_LINK_BASE_URL` в панели пуст — функция **выключена целиком**: связки никому не
рекламируются, токены не выписываются, все карточки показывают обычные ссылки подписок.
Это честное состояние «сервис склейки не развёрнут», а не ошибка.

## 2. Что сделано в этой итерации

| Где | Что сделано |
|---|---|
| Панель | Блок «Объединённые тарифы» на странице «Тарифы», кнопка «Объединить тарифы», диалог создания/правки, карточки связок с переключателем «Связка действует» и удалением |
| Панель | В связке **строго два тарифа**: третий не выбирается, объединённый тариф и тариф из чужой связки недоступны (и в интерфейсе, и на сервере) |
| Панель | Убраны поля «Подписи доп. строк в боте» для третьего и далее тарифа — они больше не существуют |
| Панель | Кнопка «Объединить тарифы» считает только свободные тарифы и объясняет в подсказке, почему неактивна |
| Панель | Тариф-связка в списке тарифов помечен бейджем «объединённый» и скрыт от покупателя; тип, трафик, лимит устройств и группы Remnawave берутся из связки |
| Панель | «Выдать подписку» у клиента умеет выдавать связку: переключатель «Что выдаём» → «Объединённая подписка (связка)», после выдачи — готовая «Ссылка для клиента» с кнопкой «Копировать» |
| Кабинет | Одна карточка на объединённую подписку вместо двух; «Трафик ∞», если в связке есть безлимит; вторая строка под трафиком не выводится |
| Кабинет | Продление объединённой подписки — одной позицией и одной оплатой (когда связка продана как тариф); попытка продлить половинки отдельно отвечает 409, а не вечным возвратом на пересчёт |
| Бот | Приветствие печатает строку трафика на каждый тариф связки: «Трафик» + «Трафик доп.» (подписи меняются в «Карте бота») |
| Сервер | Миграции БД на связки, видимый тариф, второй тариф карточки; в entrypoint добавлено автовосстановление миграции связок |
| Сборка | Образ панели собирается на 2 ГБ RAM: `NODE_OPTIONS=--max-old-space-size=2048` для `tsc` бэкенда и `tsc -b` SPA |

## 3. Как пользоваться в панели (по кнопкам)

### 3.1 Создать связку

1. Слева **«Тарифы»**.
2. В шапке страницы — кнопка **«Объединить тарифы»** (иконка слоёв, слева от «Создать тариф»).
   Кнопка неактивна, если:
   - нет права создавать тарифы → подсказка «Нет права создавать тарифы»;
   - свободных тарифов меньше двух → подсказка «Нужно два свободных тарифа: объединённые
     тарифы и тарифы из других связок не подходят».
3. В диалоге заполните:
   - **Название** — его увидит только оператор, оно же станет названием тарифа
     (подсказка в поле: «Например: Безлимит + докупка»);
   - **Описание** — необязательно;
   - **Тарифы в связке** — нажмите на два чипа. Подсказка: «Ровно два. Тариф из другой связки
     и объединённый тариф недоступны». Занятые чипы не нажимаются и объясняют причину:
     «Это объединённый тариф связки «X» — его нельзя объединить повторно» или «Этот тариф
     уже входит в другую связку». Третий чип отказывает: «В связке может быть только два тарифа».
   - **«Тариф, который виден в приложении для подключения VPN»** — чьё название, трафик и срок
     увидит клиент. По умолчанию выбран тариф с лимитом. **Безлимитный выбрать нельзя**
     («безлимитный тариф нельзя выбрать: в приложении не будет видно остаток лимита второго
     тарифа») — иначе клиент не увидит остаток второй подписки.
   - **Лимит устройств** — единственное место, где он задаётся: применяется к обоим тарифам
     связки и к уже выданным подпискам клиента. `0` — без лимита, пусто — «как у тарифа,
     видимого в приложении».
4. **«Сохранить»** → тост «Объединение создано».

После сохранения на странице появляется блок **«Объединённые тарифы»** с карточкой связки, а
в общем списке тарифов — тариф-связка с бейджем **«объединённый»**.

### 3.2 Карточка связки

Что показывает карточка:

| Элемент | Значение |
|---|---|
| Название | имя связки (= имя тарифа) |
| Чипы | оба тарифа связки |
| «Тариф: X» | тариф, которым связка выдаётся в каталоге; если он ещё не создан — «Тариф ещё не создан — сохраните связку, чтобы его создать» |
| Бейдж «виден в приложении» | стоит на тарифе, который видит VPN-клиент |
| «Устройства» | «как у тарифа, видимого в приложении» / «до N» / «0 — без лимита» |
| Переключатель **«Связка действует»** | включён — общая ссылка выдаётся; выключен — карточки показывают обычные ссылки, тариф остаётся в каталоге, сами ссылки не удаляются |
| Карандаш | «Изменить объединение» |
| Корзина | «Удалить объединение» |

### 3.3 Изменить связку

1. Карандаш на карточке → диалог «Изменить объединение».
2. Меняется всё, кроме количества тарифов: название, описание, видимый тариф, лимит устройств,
   набор тарифов (пару можно заменить на другую пару).
3. «Сохранить» → «Объединение обновлено».

### 3.4 Выключить связку, не удаляя

Переключатель **«Связка действует»** на карточке. Выключенная связка не выдаёт общую ссылку:
карточки в кабинете и боте возвращаются к обычным ссылкам подписок. Тариф связки остаётся в
«Тарифах», ссылки и подписки не трогаются — это способ «снять с продажи, но не ломать».

### 3.5 Удалить связку

1. Корзина на карточке → диалог **«Удалить объединение?»**.
2. Текст диалога прямо говорит последствия: «Связка «X» будет удалена вместе с тарифом, её
   общая ссылка перестанет работать, а карточки вернутся к обычным ссылкам подписок. Сами
   подписки не меняются.»
3. **«Удалить»** → «Объединение удалено». **«Отмена»** — ничего не меняется.

### 3.6 Выдать связку клиенту

1. **«Клиенты»** → карточка клиента → кнопка **«Выдать подписку»**.
2. Блок **«Что выдаём»** → выберите **«Объединённая подписка (связка)»**
   (вторая опция — «Один тариф»).
3. Поле **«Связка тарифов»** («Выберите связку») — в списке видны названия тарифов связки.
   Если активных связок нет: «Активных связок нет. Создайте связку на странице «Тарифы»
   кнопкой «Объединить тарифы».»
4. Задайте **«Длительность (дней)»**, при необходимости — «Пометить как триал».
5. **«Выдать объединённую»**.

Результат:

- тост «Объединённая подписка выдана: по одной подписке на каждый тариф связки»;
- в диалоге появляется блок **«Ссылка для клиента»** с кнопкой **«Копировать»** и подсказкой:
  «Ссылка заработает через несколько секунд — панель создаёт профили в Remnawave. Отправляйте
  именно её: по ней клиент получает ноды всех тарифов связки.»;
- если ссылки нет — тост объясняет причину: «Подписки созданы, но объединённой ссылки нет:
  проверьте, что связка активна и в панели задан адрес сервиса объединения
  (MERGE_LINK_BASE_URL)».

Отправляйте клиенту именно **«Ссылку для клиента»**, а не ссылку одного из тарифов.

### 3.7 Выдать один тариф из связки

Тот же диалог, но **«Что выдаём»** → **«Один тариф»**. В списке тарифов связка помечена
суффиксом **«объединённая»** — выбрать её в одиночном режиме нельзя: это не отдельный тариф,
а группировка.

### 3.8 Что меняется в каталоге тарифов

- Появляется тариф-связка с бейджем **«объединённый»** и подсказкой «Тариф связки «X»: тип,
  трафик, лимит устройств и группы Remnawave берутся из «Объединённые тарифы»». Его карточка в
  «Тарифах» не редактирует эти поля — правьте связку.
- Тариф-связка помечен **«скрыт от покупателя»**: в кассе и на витрине он не продаётся.
- Длительности и цены тарифа-связки задаются в обычной форме тарифа: по ним считается
  продление объединённой подписки (одной оплатой).

## 4. Что видит клиент

### 4.1 В VPN-приложении

- Одна подписка: название, трафик и срок — от тарифа, помеченного «виден в приложении».
- Одна ссылка: ноды обоих тарифов связки, дедуплицированные, без конфликтов имён.
- Один лимит устройств — тот, что задан в связке.

### 4.2 В кабинете (веб-приложение)

- **Одна карточка** на объединённую подписку вместо двух.
- Если в связке есть безлимитный тариф — карточка пишет **«Трафик ∞»**.
- Вторая строка трафика под карточкой **не выводится** (решение владельца от 14.11.2026:
  «в вебаппе второй тариф пусть не показывается»).
- **Продление**: если связка выдана как тариф (у него есть длительности), кабинет показывает
  одну позицию и продлевает весь набор одной оплатой. Клиент, купивший два тарифа по
  отдельности, по-прежнему продлевает их по отдельности.
- Если кабинет попытается продлить половинки как две отдельные покупки, сервер отвечает
  `409 RENEWAL_DUPLICATE_MERGED_SUBSCRIPTION` («A merged subscription is renewed as one
  product. Review the renewal again»), и страница один раз пересчитывает корзину — без
  бесконечного цикла.

### 4.3 В боте

- Приветствие печатает строку трафика на каждый тариф связки: первая — **«Трафик»**
  (основной тариф), вторая — **«Трафик доп.»**.
- Подпись второй строки меняется: **«Карта бота» → «Тексты экранов» → «Трафик доп.»**
  (ключ `profile.traffic_extra`, рядом — слот эмодзи). Это же значение — запасная подпись для
  любых дальнейших строк.
- Дополнительных полей подписи для третьего и далее тарифа больше нет: в связке их не бывает.

## 5. Настройка сервера

### 5.1 Панель Rezeis (`/opt/rezeis/.env`)

| Переменная | Значение | Если не задана |
|---|---|---|
| `MERGE_LINK_BASE_URL` | публичный адрес сервиса склейки **без завершающего слэша**, например `https://<домен-кабинета>/merge` | функция выключена: связки не рекламируются, токены не выписываются, карточки показывают обычные ссылки |

После правки `.env`: `cd /opt/rezeis && docker compose up -d --force-recreate rezeis rezeis-worker`.

### 5.2 Сервис склейки (`/opt/remnawave-subscription-merge/.env`)

| Переменная | Значение |
|---|---|
| `MERGE_REZEIS_TOKEN` | **API-токен панели** (создать: «Настройки» → вкладка «API токены»). Сервис зовёт `GET /api/internal/merge-links/<токен>/sources` |
| `REZEIS_BASE_URL` | адрес панели, если сервис на том же сервере — `http://127.0.0.1:8000` |
| `MERGE_PUBLIC_URL` | публичный адрес кабинета, например `https://<домен-кабинета>` |
| `MERGE_ADMIN_TOKEN` | локальный админ-токен самого сервиса (управление группами) |
| `MERGE_ALLOWED_HOSTS` | через запятую: домены, которые разрешено склеивать (домены нод/подписок) |
| `MERGE_SOURCES_CACHE_SECONDS` | сколько секунд кэшировать ответ панели (60 — разумно) |
| `MERGE_DATA_DIR` | постоянный каталог данных (том в compose) |

Перезапуск: `cd /opt/remnawave-subscription-merge && docker compose up -d --force-recreate merge`.

Маршруты сервиса: `/merge/<token>` (обычная подписка), `/merge/<token>/json`,
`/merge/<token>/singbox`, `/healthz` (только loopback).

### 5.3 Reverse proxy (Caddy на домене кабинета)

```caddyfile
<домен-кабинета> {
    # Объединённая подписка (remnawave-subscription-merge) — только этот префикс
    handle /merge/* {
        reverse_proxy 127.0.0.1:18080
    }
    # ... остальное как было
}
```

Проверка и перезагрузка:

```bash
caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile && systemctl reload caddy
```

### 5.4 Кабинет Reiwa

Ничего настраивать не нужно: кабинет получает уже готовую объединённую ссылку от панели.
Ему достаточно быть той же версии или новее 0.9.7.63, иначе он нарисует две карточки.

### 5.5 Внутренняя подпись запросов

`REZEIS_INTERNAL_SIGNATURE_MODE` держите `off` или `log`: сервис склейки не подписывает
внутренние запросы. При `require` его вызовы будут отклонены с 401, и ссылки перестанут
открываться.

## 6. Ограничения и отказы (что сервер не даст сделать)

| Действие | Отказ |
|---|---|
| Связка из 3+ тарифов (API) | `400 planIds must contain no more than 2 elements` |
| Объединённый тариф внутрь другой связки | `400 A merged plan cannot be a member of another bundle: <имя>` |
| Тариф, уже стоящий в другой связке | `409 Plan already grouped: <имя>` |
| Безлимитный тариф как «видимый в приложении» | `400 visiblePlanId must be one of the bundle plans` / «безлимитный тариф нельзя выбрать…» |
| Подписи доп. строк для третьего тарифа | Не принимаются: при двух тарифах `memberTrafficLabels` всегда пуст (поле оставлено только для совместимости клиентов) |
| Продажа связки через кассу | Связка скрыта от покупателя; выдаёт оператор из карточки клиента |
| Продление половинок объединённой подписки отдельными оплатами | `409 RENEWAL_DUPLICATE_MERGED_SUBSCRIPTION` |

## 7. Диагностика

| Симптом | Что проверить |
|---|---|
| «Подписки созданы, но объединённой ссылки нет» | `MERGE_LINK_BASE_URL` задан и без слэша на конце; связка включена; у клиента действительно две подписки связки; контейнер панели пересоздан после правки `.env` (`docker exec rezeis printenv MERGE_LINK_BASE_URL`) |
| Ссылка `/merge/<токен>` отвечает 404 | токен не найден: связка выключена/удалена, кэш сервиса ещё 60 с, или у клиента остался один профиль |
| В логах сервиса склейки 401 от панели | `MERGE_REZEIS_TOKEN` отозван/просрочен — создайте новый API-токен и перезапустите контейнер сервиса |
| В кабинете две карточки вместо одной | кабинет старее 0.9.7.63, либо панель не отдала блок `merge` (связка выключена, `MERGE_LINK_BASE_URL` пуст) |
| В боте только одна строка трафика | у клиента одна подписка связки, либо бот старее 0.9.7.63 |
| Бот пишет `ECONNREFUSED` сразу после перезапуска панели | нормально: бот ждёт панель и переподключается сам («the panel answers again») |
| Кнопка «Объединить тарифы» неактивна | свободных тарифов меньше двух: тариф уже в связке или сам является объединённым |

Быстрые проверки на сервере:

```bash
curl -fsS http://127.0.0.1:18080/healthz                 # сервис склейки жив
curl -fsS https://<домен-кабинета>/merge/healthz         # маршрут через Caddy
docker exec rezeis printenv MERGE_LINK_BASE_URL          # панель знает адрес склейки
docker logs --tail 50 remnawave-subscription-merge       # 401/404 по токенам
```

## 8. API (для автоматизации)

| Метод и путь | Назначение | Право |
|---|---|---|
| `GET /api/admin/plan-bundles` | список связок | `plans:view` |
| `POST /api/admin/plan-bundles` | создать (`name`, `planIds[2]`, `visiblePlanId?`, `deviceLimit?`, `secondaryPlanId?`, `isActive?`, `description?`) | `plans:create` |
| `PATCH /api/admin/plan-bundles/:id` | изменить | `plans:edit` |
| `DELETE /api/admin/plan-bundles/:id` | удалить вместе с тарифом | `plans:delete` |
| `GET /api/internal/merge-links/:token/sources` | источники по токену (зовёт сервис склейки) | API-токен панели |

**Rezeis (панель)**

## 10. Текущее состояние установки

- Панель `tin.cloudre.store` (Rezeis Admin 0.9.7.81), кабинет и бот `stin.cloudre.store`
  (Reiwa 0.9.7.63), сервис склейки — `https://stin.cloudre.store/merge`, контейнер
  `remnawave-subscription-merge` на loopback `127.0.0.1:18080`.
- В каталоге 6 тарифов: 2 связки по 2 тарифа + 2 тарифа-связки. **Свободных тарифов нет**,
  поэтому кнопка «Объединить тарифы» сейчас неактивна — это ожидаемо. Чтобы создать новую
  связку, выведите тариф из старой (карандаш на карточке связки) или создайте новый тариф.
- Версии панели, кабинета и бота совместимы между собой; кабинет подхватывает объединённые
  ссылки автоматически.

## 11. Чек-лист «всё работает»

1. В панели: «Тарифы» → есть карточка связки, переключатель «Связка действует» включён.
2. В `.env` панели: `MERGE_LINK_BASE_URL=https://<домен>/merge` (без слэша); контейнер
   пересоздан (`docker exec rezeis printenv MERGE_LINK_BASE_URL` печатает значение).
3. `curl -fsS https://<домен>/merge/healthz` отвечает 200.
4. Клиенту выдана связка: в карточке клиента показана «Ссылка для клиента», она содержит
   `/merge/`.
5. Клиент открыл ссылку: в приложении одна подписка, видны ноды обоих тарифов.
6. В кабинете у клиента одна карточка; в боте приветствие с двумя строками трафика.
